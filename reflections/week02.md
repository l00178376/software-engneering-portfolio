# Task Two
### Project Presented
**Project:** Aegis Flight-Control Software Update  
**Chosen Process Model:** Waterfall

### My Presentation
I chose the **Waterfall model** because the requirements for the flight-control software are stable and clearly defined. The project has very high safety risks, so it requires detailed documentation, testing and traceability. The 12–18 month certification timeline also means that rapid development is not the main priority.

### Challenge / Question
My classmate asked whether **RUP** could be a better choice because it also provides strong documentation, testing and risk management.

### My Response
RUP could be considered because it supports risk management and detailed documentation. However, I chose Waterfall because the requirements are already well understood and stable, making a structured sequential process suitable for this project.

### Did People Choose Differently?
Yes. Some people chose **RUP** instead of Waterfall.

The main reason was that RUP provides an iterative approach and focuses strongly on identifying and managing risks throughout development. Others chose Waterfall because the requirements are stable and the project requires strict documentation and traceability.

### Reflection
The discussion showed that more than one process model can be appropriate for the same project. The choice depends on which project characteristics are given the most importance, such as requirement stability, risk management, documentation and customer involvement.

# Task 3 — Portfolio Entry
For my hypothetical software project, I would develop a tennis training app that helps players improve their skills. The app could include training exercises, match statistics, progress tracking and personalised practice suggestions.

I would choose the Incremental process model because the requirements could change as players use the app and provide feedback. Instead of building everything at once, the team could first release basic features such as training exercises and player profiles. Later increments could add match statistics, progress tracking and personalised recommendations.

Customer involvement would be important because tennis players may have different training needs and could suggest useful features. The incremental approach would allow the development team to respond to this feedback throughout the project.

The project has relatively low safety risks, so frequent releases and feedback would be more important than extensive documentation. Overall, the Incremental model would allow the tennis app to develop gradually while delivering useful features to players early.
