Task 3 — Extreme Programming (XP) Practice
Selected Practice: Continuous Integration (CI)

Continuous Integration is an XP practice where developers frequently merge their code into a shared codebase and automatically run builds and tests to identify problems early. A real-world example is GitHub, which uses GitHub Actions to build and test GitHub.com; its engineering team reported scaling its CI system to run around 15,000 jobs within an hour. Source: GitHub Engineering Blog.

In my PitchPerfect Scrum/Kanban simulation, CI would help the team check each small change to features such as viewing available pitch slots, making bookings, and sending confirmation emails before moving stories to Done. This would catch bugs early, reduce integration problems, and give the team more confidence when delivering work quickly. However, slow automated tests or unreliable test results could delay progress, so the team would need to keep its test pipeline reliable and efficient.
